## 1. ビジネスモデル（事業計画マスターの前提）

**国内フリマ（メルカリ）で型番が明確な中古品を仕入れ、eBay（主に米国）で売る、有在庫型の越境アービトラージ。**

| 項目 | 12か月目・基準計画 | 出典（シート） |
|---|---|---|
| 月間営業利益 | 450万円（下振れ300 / 上振れ606） | 前提条件 |
| 月間販売数 | 300件 | 12ヶ月計画 |
| 平均販売単価 / 平均仕入単価 | 62,000円 / 25,000円 | ユニットエコノミクス |
| 貢献利益/件 | 19,000円（仕入ROI 76%） | ユニットエコノミクス |
| 在庫日数 | 50日 | 前提条件 |
| カテゴリ構成 | カメラ・レンズ45% / ゲーム・限定品20% / 音響・楽器20% / その他15% | カテゴリ別採算 |
| 供給量KPI | 購入成功320件/月（取得60,000件 → 販売300件） | 仕入れファネル |

**利益の式（貢献利益）**

```
売価 − eBay手数料（FVF 13.25%＋$0.30＋海外手数料1.35%） − 広告2% − 米国関税（DDP） − 換金スプレッド2%
     − 返品・値下げ・為替引当1.6% − 仕入 − 国際送料 − 梱包資材 − 作業費   ＝ 貢献利益
仕入ROI ＝ 貢献利益 ÷ 仕入価格
```

事業を伸ばすレバーは4つ:
1. **1件あたりの貢献利益**
2. **回転**（在庫日数）
3. **件数**（供給量と処理能力）
4. **失敗率**（誤仕入れ・返品・予測誤差）

計画は「ステージゲート」で、達成していなければ資金を絞る設計になっている。

## 2. 外部環境の分析（2026-10-16 時点）

詳細と出典は `flipbot/knowledge/environment.yaml` を参照（ツールの「外部環境」ページにも表示）。

### 2-1. 販売先：eBay

| 変化 | 時期 | 影響 | 評価 |
|---|---|---|---|
| 売れた商品（Sold）の閲覧にログインが必須（報道。ツールでも403/CAPTCHAを確認） | 2026-07-22〜 | 相場データの取得が難しくなり、データを持つ側が有利になる | 逆風 |
| 米国向け（2,500ドル未満）はDDPが必須。DDUで関税トラブルになるとSeller faultでDefectが付く | 2025-10-17〜 | 関税がセラーの負担になる。FVFも関税込みの総額にかかる | 逆風 |
| 手数料 = FVF 13.25〜13.6%＋0.30〜0.40ドル＋海外手数料1.35% | 継続 | 合計で約15〜17%。計画シートの15%とほぼ一致するが、換金スプレッドが計画に入っていない | 要注意 |
| 需要トレンド：2026年Q1はトレカが成長率1位、時計が3年半ぶりにTOP3。Q2は鑑定済み漫画・ONE PIECEカード。デジカメ中古が好調（2025） | 2025〜2026 | カメラ（主力45%）は追い風。成長の中心はトレカ・時計（計画では保留・後回し） | 追い風 |
| 米国の制度変更後、英国・豪州・欧州・アジアへの販路拡大 | 2025〜 | 米国以外での販売比率が利益の安定に効く | 機会 |
| 法人の強いセラー（eBay Japan Awards：キタムラ／モトヤ／コレクト／SEVEN 等） | 2026-03 | 仕入れ量では勝てない。照合精度・速度・検品品質で差別化する | 要注意 |

### 2-2. 物流・関税

| 変化 | 時期 | 影響 |
|---|---|---|
| IEEPA相互関税（日本15%）が最高裁で違法となり失効 → 通商法122条の一律10%は2026-07-24で期限 → **その後の扱いは未確認** | 2026-02〜07 | 米国向けの利益が5〜10%前後振れる。ツールは関税率10%×米国比率50%で仮置き（**要確認**） |
| 日本郵便の米国宛てが2026-04-14に再開（指定局・DDP・関税の事前払い）。7/24から事前払いの上限が2,500ドルに拡大 | 2026-04〜 | 小型のレンズ・電子機器は郵便ルートで送料を下げられる可能性 |

### 2-3. 仕入れ先：メルカリ

| 変化 | 影響 |
|---|---|
| **メルカリ グローバルアプリ**：海外の買い手がメルカリの出品を直接購入。越境GMVは1,122億円（全体の約9%）で、4年で19倍。取引の56.9%はアニメ・ゲーム | 仕入れ先そのものが販売チャネルになった。**アニメ・ゲームは海外の買い手と仕入れを取り合う**ため、価格差が縮みやすい |
| 取引の基本原則を改定（2025-10、悪質転売の抑止・出品禁止の特例）。事業者の利用制限の報道もある（一次情報は未確認） | 事業としての仕入れ方法・自動取得の可否が、事業継続のリスクになる（タスクP03が未着手） |
| 型番商品の出品は業者（返品保証・管理番号付き）が多い（ツールの実取得で確認：Nikon 50mm F1.4の検索結果） | 個人の「掘り出し」だけでなく、業者出品との価格差・状態ランクの差を取りに行く設計が必要 |

### 2-4. 為替・マクロ

- ドル円は157〜158円（2026年10月上旬）。円安は追い風。1円の円高で、売価62,000円あたり約400円の利益が減る。
- 計画シートの前提為替は明記されていない → **シートに為替前提の欄を設けることを推奨**。ツールは自動で取得する。

### 2-5. 戦略への示唆

1. **相場データの確保が最優先。** ログイン済みブラウザ・Product Research・公式APIの3本立てで、「相場が取れない日」をなくす。
2. **計画シートのユニットエコノミクスに関税（DDP）と換金スプレッドを追加すべき。** 基準ケース（売価62,000・仕入25,000・送料5,500）の貢献利益は、ツールの計算では18,000円ではなく**約14,100円**になる（関税で約3,100円、換金で約970円の差）。このままだと下振れ300万円ラインの前提が甘くなる。
3. **ゲーム・限定品は20%以内に抑え、カメラ・レンズと型番が明確な楽器で利益を作る**（メルカリの越境化と整合）。
4. **米国以外への販売比率を高める**（関税の不確実性を薄める）。
5. **規約の確認（P03）を最優先で。** 取得は低頻度・購入は人の手で行う運用を守る。

## 4. 計画シートとツールの役割分担（考察）

**原則：数値の正本はシート（意思決定ログ 2026-07-21）。ツールは計画値を読み込むだけで書き換えず、実績を自動で作って、シートへ戻しやすくする。**

| シートのタブ | ツールに含めたか | 理由・使い方 |
|---|---|---|
| 12ヶ月計画 / KPI実績 | **含めた（読込＋実績の自動集計）** | 計画対実績を毎日見る必要がある。実績の手入力をなくし、シートには週1回貼り付けるだけにする |
| 仕入れファネル | **含めた** | 取得・候補・確認・購入・検品・出品・販売の件数は、ツールのログから正確に数えられる |
| カテゴリ別採算 / 資金配分ルール | **含めた** | 下限利益として候補の足切りに直接使う。配分ルールは仕入れ時の判断に必要 |
| リスク管理 / ステージゲート | **含めた（自動判定）** | 先行指標はツールのデータから計算できる。発動を見逃さないことが目的 |
| 当たりジャンル商品DB | **含めた（カバー率）** | どの仮説を監視・検証しているかを見える化。監視ジャンルにIDを紐づけた |
| 意思決定ログ（有効分） | **含めた（参照＋ツールへの反映状況）** | 決定がツールの挙動にどう反映されたかを残す |
| タスク管理 | **含めた（読み取り専用）** | 期限切れ・今週のタスクを実務画面の隣に出す。更新はシート |
| ユニットエコノミクス / シナリオ / ダッシュボードの経営判断 | **含めた（表示）** | 判断基準として表示。費用構成は利益計算に反映 |
| 前提条件 | 一部 | 目標値の表示に使用。費用の前提は config.yaml と二重になるため、将来はシートから読む |
| 資金繰り / 予定PL / 予定CF | 含めない（在庫の内訳だけ） | 融資・税金・固定費は会計の領域。ツールは在庫の内訳（未到着・検品出品待ち・販売可能・未入金）を提供 |
| 作業工数 | 含めない | 作業時間を計測する仕組みが前提。将来はSKUの工程時刻から推定できる |
| 競合ベンチマーク | 含めない | 定性的なリサーチ資料。外部環境ページの「競合」に要点だけ反映 |
| 運用ルール / チャット抽出データ | 含めない | 運用上のメタ情報 |

### シート側への提案

1. **ユニットエコノミクスに「米国関税（DDP）」「換金スプレッド」の行を追加する**（基準の貢献利益が約3〜4千円下がる可能性）。
2. **前提条件に「為替（円/ドル）」「米国の買い手比率」「関税率」を追加する。** ツールがそこから読めるようになり、config.yaml との二重管理がなくなる。
3. **タスク管理のステータスが全件「未着手」のままで、期限切れが多い。** 実装済みのタスク（P10・P12・P13・S04・S14・S17 など）はツールの「計画タスク」ページで対応を確認し、ステータスを更新する。
4. **P03（メルカリ規約の確認）を最優先にする。** 外部環境で最大のリスク。
