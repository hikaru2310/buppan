# メルカリ→eBay 物販：ビジネスフロー別 ツール改善候補

最終更新: 2026-10-02

## 1. ビジネスモデルの整理

**国内フリマ（メルカリ）で仕入れ、海外（eBay・主に米国）で売る「有在庫型の越境アービトラージ」**。
儲けの源泉は「日本でしか安く手に入らない物（レトロゲーム機・フィルムカメラ・限定品など）」と「海外の需要・価格」の差です。

### 1件あたりの損益（ツールの計算式）

```
受取額 = (eBay売価 − eBay手数料[FVF 13.25% + $0.30]) × 為替 × (1 − 換金スプレッド 2%)
総原価 = メルカリ仕入値 + 国際送料 + 梱包・雑費
利益   = 受取額 − 総原価          ROI = 利益 ÷ 総原価
```

### 事業として伸ばすときに効くレバー

| レバー | 意味 | 効く場所 |
|---|---|---|
| ① 1件あたり利益 | 安く買い、高く売り、コストを削る | リサーチ・仕入れ判断・出品・発送 |
| ② 回転数 | 仕入れてから入金までの日数（キャッシュサイクル）を縮める | 受取〜出品〜販売〜入金 |
| ③ 件数（スループット） | 1日に処理できる件数を増やす | 全工程の手作業を減らす |
| ④ 失敗率 | 誤マッチ・状態不良・返品・破損・赤字売却を減らす | 判断・検品・梱包・販売後 |

**資本の伸び ≒ 1回転あたりROI × 月の回転数 × 稼働率**です（資本シミュレーターの式）。
ROIだけでなく、**回転数（何日で現金に戻るか）**が同じくらい効きます。今のツールが見ているのは①の一部（仕入れ前の判断）だけです。

## 2. フロー全体と現状

```
①ジャンル選定 → ②リサーチ → ③仕入れ判断 → ④購入 → ⑤受取・検品・撮影
   → ⑥出品 → ⑦販売・価格調整 → ⑧受注・梱包・発送 → ⑨入金・換金 → ⑩分析・再投資 → ①へ
```

| 工程 | 今のツール | 手作業の量 |
|---|---|---|
| ①ジャンル選定 | config.yaml に手で記述 | 中 |
| ②リサーチ | **自動**（メルカリ新着＋eBay成約を収集・照合） | 少 |
| ③仕入れ判断 | **自動**（実質利益・ROI・損益分岐・マッチ度・根拠リンク） | 少 |
| ④購入 | 「仕入れる」でメルカリを開く／キュー・取引履歴 | 中 |
| ⑤受取・検品・撮影 | なし | **多** |
| ⑥出品 | なし | **多** |
| ⑦販売・価格調整 | なし | 中 |
| ⑧梱包・発送 | なし | **多** |
| ⑨入金・換金 | 換金スプレッドを計算に含めるだけ | 少 |
| ⑩分析・再投資 | 資本シミュレーター（想定値のみ） | 中 |

## 3. 矢羽ごとの改善候補

優先度: **A** = すぐ効く／**B** = 次に効く／**C** = 将来
工数: 小（〜1日）／中（数日）／大（1週間〜）

### ① ジャンル選定 → ② リサーチ

**課題**: どのジャンルを監視するかが勘頼みです。外れたジャンルを監視してもスキャン時間を食うだけで、当たりのジャンルを見逃しても気づけません。

| # | 改善候補 | 効果 | 優先 | 工数 |
|---|---|---|---|---|
| 1-1 | **ジャンル成績表**：ジャンルごとに「走査件数・候補化率・平均ROI・見送り率・相場なし率」を集計して表示 | 外れジャンルを外し、当たりに寄せる | A | 小 |
| 1-2 | ジャンル定義を画面から追加・編集（今は config.yaml） | 試行回数が増える | B | 中 |
| 1-3 | ジャンル候補の自動提案：eBay成約が多く単価が高い日本製品のキーワードを、成約データから抽出 | 新しい儲かる領域の発見 | C | 大 |
| 1-4 | 検索語のバリエーション自動生成（型番違い・表記ゆれ・色違い） | 取りこぼしを減らす | B | 中 |

### ② リサーチ → ③ 仕入れ判断

**課題**: 精度の大半は「メルカリ品とeBay成約品の突き合わせ（マッチング）」で決まります。さらに今は、**eBayの成約データがログインなしでは取れない**ことがボトルネックです。

| # | 改善候補 | 効果 | 優先 | 工数 |
|---|---|---|---|---|
| 2-1 | **eBayログイン状態の維持**（今回追加：画面のボタンからログイン、成約データを12時間キャッシュ） | 実データで候補が出る前提条件 | A | 済 |
| 2-2 | eBay公式API（Browse API＝出品中の価格）で補完し、成約が取れない時も「出品中の最安値」で暫定相場を出す | ブロック時も止まらない | A | 中 |
| 2-3 | **見送り理由「商品違い」から辞書を育てる**：誤マッチだった組み合わせを記録して、次回の照合で減点する | 精度が使うほど上がる | A | 中 |
| 2-4 | 画像での照合（メルカリ画像とeBay画像の類似度） | 型番のない商品で精度が上がる | C | 大 |
| 2-5 | 状態（美品／ジャンク／箱あり／欠品）をタイトル・説明文から推定し、相場を状態別に分ける | 「箱付きの相場で箱なしを買う」事故を防ぐ | B | 中 |
| 2-6 | 成約の新しさで重み付け（直近30日を重視）、外れ値の除外（極端な高値・安値） | 相場のブレを減らす | B | 小 |
| 2-7 | 為替の自動取得（毎朝） | 円安・円高の局面で判断がずれない | A | 小 |
| 2-8 | **販売速度（売れるまでの日数）の推定**：成約件数÷期間で「月に何個売れるか」を出す | 回転数（レバー②）を判断に入れる | A | 中 |

### ③ 仕入れ判断 → ④ 購入

**課題**: 良い出品はすぐ売れてしまいます。見つけてから買うまでの速さが勝負です。

| # | 改善候補 | 効果 | 優先 | 工数 |
|---|---|---|---|---|
| 3-1 | **新着通知**：基準を満たす新着が出たら即LINE／Slack／メールに通知（商品ページURL・利益・ROI付き） | 早い者勝ちに勝つ | A | 小 |
| 3-2 | 監視間隔をジャンル別に変える（回転の速い人気ジャンルは5分、その他は30分） | アクセス負荷を抑えつつ速さを確保 | B | 小 |
| 3-3 | 出品者の評価・出品からの経過時間・値下げ交渉可否を表示 | トラブルの回避と値下げ余地の把握 | B | 中 |
| 3-4 | 1日の仕入れ予算（資本上限）を設定し、キュー合計が超えたら警告 | 資金繰りの事故を防ぐ | B | 小 |
| 3-5 | 「惜しい候補」に**指値**を表示：いくらまで値下げしてもらえれば基準に届くか（＝値下げ交渉の目安） | 候補数が増える | A | 小 |

### ④ 購入 → ⑤ 受取・検品・撮影

**課題**: 届いた物が説明と違う、動かない、付属品がない、といった失敗がここで発覚します。記録が残らないため、同じ失敗を繰り返します。

| # | 改善候補 | 効果 | 優先 | 工数 |
|---|---|---|---|---|
| 4-1 | **在庫台帳**：取引履歴 →「到着待ち → 検品OK/NG → 出品待ち」の状態管理 | 何がどこにあるか分かる | A | 中 |
| 4-2 | ジャンル別の検品チェックリスト（例：ゲーム機＝起動・音・液晶・電池端子） | 品質のばらつきを減らす | B | 小 |
| 4-3 | 検品NG時の取引キャンセル・評価対応のメモと、ジャンル別の不良率集計 | 不良率の高いジャンルや出品者を避ける | B | 小 |
| 4-4 | 撮影ガイド（必要カット一覧）と、写真をフォルダに入れたら商品に自動で紐づけ | 出品準備の時短 | C | 中 |

### ⑤ 受取・検品・撮影 → ⑥ 出品

**課題**: 英語タイトル・説明文・Item specifics（項目情報）・送料設定は、手作業だと1件10〜20分かかります。件数を増やすうえで最大のボトルネックです。

| # | 改善候補 | 効果 | 優先 | 工数 |
|---|---|---|---|---|
| 5-1 | **出品下書きの自動生成**：相場の根拠にしたeBay成約品のタイトル・Item specifics を流用し、英語タイトル・説明文・推奨価格を作る | 出品時間を数分に短縮 | A | 中 |
| 5-2 | eBay Trading / Inventory API での一括出品 | 件数（レバー③）を大きく伸ばせる | B | 大 |
| 5-3 | 推奨開始価格＝成約中央値×係数、Best Offer の自動承諾・自動拒否ラインを損益分岐から設定 | 交渉の手間と赤字売却を減らす | B | 小 |

### ⑥ 出品 → ⑦ 販売・価格調整

**課題**: 売れ残りは資本を寝かせ、回転数を下げます。値下げのタイミングが勘任せです。

| # | 改善候補 | 効果 | 優先 | 工数 |
|---|---|---|---|---|
| 6-1 | **在庫エイジング**：出品からの日数・閲覧数・ウォッチ数を表示し、売れ残りを可視化 | 寝ている資本に気づける | A | 中 |
| 6-2 | **自動値下げルール**：例）14日売れなければ5%下げ、ただし損益分岐は割らない | 回転数（レバー②）の改善 | B | 中 |
| 6-3 | 相場の再チェック：出品中の商品の相場が下がったら通知 | 値崩れ前に売り切る | B | 小 |

### ⑦ 販売 → ⑧ 受注・梱包・発送

**課題**: 発送遅延はセラー評価を下げます。送料の見積もりと実費の差は、利益の誤差になります。

| # | 改善候補 | 効果 | 優先 | 工数 |
|---|---|---|---|---|
| 7-1 | **出荷キュー**：売れた注文・宛先・期限・配送方法を一覧にし、期限が近いものを強調 | 遅延の防止 | B | 中 |
| 7-2 | 配送方法の自動選択（重量・サイズ・国・関税条件ごとに最安・最速を提案）と、送料実費の記録 | 送料の誤差をなくし、利益計算に反映 | A | 中 |
| 7-3 | 米国向けの関税・DDP（関税込み配送）の扱い整理 ※米国の少額免税（デミニミス）停止以降の最新ルールは要確認 | 買い手の受取拒否・返品の防止 | A | 小（調査） |
| 7-4 | 追跡番号のeBayへの自動反映 | 手作業の削減 | C | 中 |

### ⑧ 発送 → ⑨ 入金・換金

**課題**: 入金・換金のタイミングが分からないと、資金繰りが見えません。

| # | 改善候補 | 効果 | 優先 | 工数 |
|---|---|---|---|---|
| 8-1 | 入金予定・換金の記録（売上日 → eBay入金 → Payoneer/Wise → 円の口座） | キャッシュサイクルが見える | B | 小 |
| 8-2 | 換金スプレッド・為替の実績値を記録し、計算の前提（2%）を更新 | 利益計算の精度 | B | 小 |

### ⑨ 入金 → ⑩ 分析・再投資 → ① に戻る

**課題**: 想定利益と実際の利益の差を見ていないので、計算の前提（送料・手数料・相場）が正しいか検証できません。

| # | 改善候補 | 効果 | 優先 | 工数 |
|---|---|---|---|---|
| 9-1 | **想定 vs 実績の突き合わせ**：1件ごとに「想定利益 → 実際の売価・送料・手数料 → 実利益」を記録 | 計算の前提を実績で補正できる | A | 中 |
| 9-2 | 実績ベースの資本シミュレーター（実際のROI・回転日数・売れ残り率を自動で入力） | 再投資の判断が現実的になる | B | 小 |
| 9-3 | 月次P/L・CSV（確定申告・帳簿用）、消費税・輸出免税の扱いメモ ※税務の扱いは税理士に要確認 | 経理の手間の削減 | B | 中 |
| 9-4 | 実績を①ジャンル成績表（1-1）に戻す：利益が出たジャンルの監視を自動で厚くする | フロー全体が学習して回る | B | 中 |

## 4. おすすめの実装順

最初の4つで、「実データで候補が出る → 速く買える → 回転が見える」状態になります。

1. **eBayログイン（済）→ 2-2 公式APIでの補完 → 2-7 為替の自動取得**：実データで候補を安定して出す
2. **3-1 新着通知 → 3-5 指値表示**：見つけた良品を確実に取る
3. **2-8 販売速度 → 1-1 ジャンル成績表**：ROIだけでなく回転で選ぶ
4. **4-1 在庫台帳 → 6-1 在庫エイジング → 9-1 想定vs実績**：仕入れた後を見える化し、計算の前提を検証する
5. **5-1 出品下書きの自動生成**：件数を伸ばす最大のボトルネックを解消する
6. その後に 6-2 自動値下げ、7-1 出荷キュー、5-2 API出品（打ち合わせで話に出た「販売側の自動化」）

## 5. 指標（KPI）案

| 工程 | 指標 |
|---|---|
| リサーチ | 走査件数／日、候補化率、相場なし率 |
| 判断 | 候補 → 購入の転換率、見送り理由の内訳（特に「商品違い」） |
| 仕入れ | 購入から到着までの日数、検品NG率 |
| 出品 | 到着から出品までの日数、1件あたりの出品時間 |
| 販売 | 出品から販売までの日数（回転）、値下げ回数、売れ残り率 |
| 発送 | 発送までの日数、送料の想定と実費の差 |
| 全体 | 想定利益と実利益の差、実ROI、キャッシュサイクル（購入から円入金までの日数） |
